# ansible-role-mongodb v2.0.0 Foundation Refactor — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor `maprangzth/ansible-role-mongodb` to v2.0.0 — drop MongoDB 3.4–5.0 + SSL legacy + MMS + Amazon Linux; add MongoDB 7.0/8.0 + 6.0 (deprecated tier); cover RHEL/Rocky 9 (primary) + 8 (nightly), Debian 12, Ubuntu 22.04/24.04; amd64 + arm64; ship as clean-break v2.0.0.

**Architecture:** Hybrid decision gate — Phase 1 runs a 3-day timeboxed B-spike against `community.mongodb` collection. If spike pass criteria hold → Approach B (delegate install/configure to upstream roles, keep value-add: users, exporter, logrotate). If spike fails → fall back to Hybrid (Approach A: strip-and-modernize in-place). This plan documents Approach B as primary path with `[HYBRID DELTA]` callouts for Approach A divergences.

**Tech Stack:** Ansible (ansible-core 2.15+), `community.mongodb` collection (1.7+), MongoDB 6.0/7.0/8.0, PyMongo 4.6+, Python 3.9+, Molecule + Docker, GitHub Actions, Rocky Linux / Debian / Ubuntu base images.

**Reference spec:** `docs/superpowers/specs/2026-05-22-mongodb-modernization-design.md` v1.1

**Branching:**
- Phase 0 cuts `v1.x` from current `master` HEAD, then renames `master` → `main`, points new `master` to `v1.x`
- Phase 1 work on `spike/community-mongodb-eval`
- Phase 2+ work on `refactor/v2.0-foundation`, merged to `main`

### Task 0.2: Snapshot MongoDB × OS × architecture support matrix

**Files:**
- Create: `docs/SUPPORT-MATRIX.md`
- Create: `scripts/probe-mongodb-repos.sh`

**Why:** Spec §6.4 references a support matrix. Need a reproducible probe + checked-in snapshot to validate `validate.yml` assertions.

- [ ] **Step 1: Write the probe script**

```bash
cat > scripts/probe-mongodb-repos.sh <<'EOF'
#!/usr/bin/env bash
# Probe MongoDB repos for (version × OS × arch) availability.
# Output: tab-separated rows: <mongodb>\t<os>\t<arch>\t<http_code>
set -u

declare -a MONGO_VERSIONS=(6.0 7.0 8.0)

probe() {
  local url="$1"
  curl -sI -o /dev/null -w "%{http_code}" "$url"
}

# Debian + Ubuntu (apt)
for v in "${MONGO_VERSIONS[@]}"; do
  for codename in bullseye bookworm trixie jammy noble; do
    case "$codename" in
      bullseye|bookworm|trixie) flavor=debian ;;
      jammy|noble)              flavor=ubuntu ;;
    esac
    url="https://repo.mongodb.org/apt/${flavor}/dists/${codename}/mongodb-org/${v}/Release"
    code=$(probe "$url")
    printf "%s\t%s/%s\t%s\t%s\n" "$v" "$flavor" "$codename" "any" "$code"
  done
done

# RHEL/Rocky/Alma (yum)
for v in "${MONGO_VERSIONS[@]}"; do
  for relver in 8 9 10; do
    for arch in x86_64 aarch64; do
      url="https://repo.mongodb.org/yum/redhat/${relver}/mongodb-org/${v}/${arch}/RPMS/"
      code=$(probe "$url")
      printf "%s\t%s/%s\t%s\t%s\n" "$v" "redhat" "$relver" "$arch" "$code"
    done
  done
done
EOF
chmod +x scripts/probe-mongodb-repos.sh
```

- [ ] **Step 1: Generate test certs (one CA, member certs, cluster cert)**

```bash
mkdir -p tests/spike-inventory/certs
cd tests/spike-inventory/certs

openssl req -x509 -newkey rsa:2048 -days 30 -nodes \
  -keyout ca.key -out ca.pem -subj '/CN=spike-ca'

for host in cfg01 cfg02 cfg03 shard1-01 shard1-02 shard1-03 mongos01; do
  openssl req -newkey rsa:2048 -nodes \
    -keyout $host.key -out $host.csr -subj "/CN=$host"
  openssl x509 -req -in $host.csr -CA ca.pem -CAkey ca.key -CAcreateserial \
    -out $host.crt -days 30
  cat $host.crt $host.key > $host.pem
done

openssl req -newkey rsa:2048 -nodes \
  -keyout cluster.key -out cluster.csr -subj '/CN=spike-cluster'
openssl x509 -req -in cluster.csr -CA ca.pem -CAkey ca.key -CAcreateserial \
  -out cluster.crt -days 30
cat cluster.crt cluster.key > cluster.pem
cd -
```

# v1.x → v2.0.0 Migration Guide

## Prerequisites before applying v2.0.0

1. **Upgrade MongoDB manually first if on ≤ 5.0.** MongoDB does not support skipping major versions. Upgrade step-wise: `4.4 → 5.0 → 6.0 → 7.0 → 8.0`. After each step, run `db.adminCommand({setFeatureCompatibilityVersion: "<new-major>", confirm: true})`.

2. **RHEL 8 only:** install python3.9 and set `ansible_python_interpreter: /usr/bin/python3.9` in inventory `group_vars/`. The role's `install.requirements` task installs python3.9, but Ansible must be told which interpreter to use. Default `/usr/libexec/platform-python` is Python 3.6 and will fail.

3. **Pin your installs to a tag, not a branch.** v1.x users with `git+...,master` will resolve to v1.x for ~1 release, then break.

## Removed variables (must remove from your group_vars)

| v1 variable | Action |
|---|---|
| `mongodb_net_ssl_enabled` | Remove. Use `mongodb_net_tls_enabled` instead. |
| `mongodb_net_ssl_config` (dict) | Remove. Replace with flat `mongodb_net_tls_*` vars (table below). |
| `mongodb_net_ssl_PEMKeyFile_path` | Remove. Use `mongodb_net_tls_certificateKeyFile`. |
| `mongodb_net_ssl_CAFile_path` | Remove. Use `mongodb_net_tls_CAFile`. |
| `mongodb_net_ssl_CRLFile_path` | Remove. Use `mongodb_net_tls_CRLFile`. |
| `mongodb_net_ssl_clusterFile_path` | Remove. Use `mongodb_net_tls_clusterFile`. |
| `mongodb_net_ssl_clusterCAFile_path` | Remove. Use `mongodb_net_tls_clusterCAFile`. |
| `mongodb_mms_*` | Remove. MMS agent dropped. Use Atlas or separate deployment. |
| `mongodb_cloud_*` | Remove. Free cloud monitoring deprecated upstream. |
| `mongodb_storage_quota_*` | Remove. mmapv1 storage engine dropped in MongoDB 4.2. |
| `mongodb_storage_smallfiles` | Remove (same). |
| `mongodb_storage_prealloc` | Remove (same). |
| `bin_arch` | Remove. Auto-derived now (`mongodb_apt_arch` / `mongodb_rpm_arch` / `mongodb_exporter_arch`). |

## TLS migration (v1 nested → v2 flat)

| v1 key | v2 variable |
|---|---|
| `mongodb_net_ssl_config.mode` | `mongodb_net_tls_mode` |
| `mongodb_net_ssl_config.allowInvalidCertificates` | `mongodb_net_tls_allowInvalidCertificates` |
| `mongodb_net_ssl_config.allowInvalidHostnames` | `mongodb_net_tls_allowInvalidHostnames` |
| `mongodb_net_ssl_config.FIPSMode` | `mongodb_net_tls_FIPSMode` |
| `mongodb_net_ssl_config.disabledProtocols` | `mongodb_net_tls_disabledProtocols` |

## New required variables

- `mongodb_security_keyfile_content` (was optional in v1, required when replicaset enabled in v2)
- Explicit `ansible_python_interpreter` on RHEL 8

## Example diff

Before (v1.6.5):
```yaml
mongodb_version: "4.4"
mongodb_net_ssl_enabled: true
mongodb_net_ssl_config:
  mode: requireSSL
  PEMKeyFileContent: "{{ vault_cert }}"
mongodb_mms_api_key: "{{ vault_mms_key }}"
```

After (v2.0.0):
```yaml
mongodb_version: "8.0"
mongodb_net_tls_enabled: true
mongodb_net_tls_mode: requireTLS
mongodb_net_tls_certificateKeyFile: /etc/ssl/mongo/server.pem  # placed by operator
mongodb_net_tls_CAFile: /etc/ssl/mongo/ca.pem
# MMS removed — deploy Cloud Manager agent separately
```
